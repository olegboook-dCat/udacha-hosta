# Удача — кафе в Хосте

Одностраничный сайт кафе «Удача» (Сочи, Хоста, Платановая ул., 4/4). Статический HTML/CSS/JS без фреймворков и серверных функций.

- `src/` — исходники: `index.html`, `css/style.css`, `js/main.js`, SVG-графика (лист банана, иконка).
- `photos.json` — фото кафе и гостей из карточки на Яндекс Картах (id изображений на avatars.mds.yandex.net).
- `hero/` — фото первого экрана, локальный файл (улучшенная версия снимка веранды из карточки, 1760×1320, AVIF). Лежит в виде base64-частей `hero.avif.b64.1…4`: GitHub-коннектор умеет класть в репозиторий только текст. `build.mjs` склеивает и декодирует их при сборке; остальные фото по-прежнему скачиваются с Яндекса.
- `build.mjs` — собирает готовый сайт в `dist/`: копирует `src/`, скачивает фото и сжимает их в webp (sharp), кладёт шрифты Yeseva One, Manrope и Caveat (кириллица и латиница, woff2 из пакетов @fontsource) прямо в проект, делает иконки и картинку для соцсетей, подставляет адрес сайта, пишет `robots.txt`, `sitemap.xml` и `.htaccess`.
- `hosting/htaccess` — шаблон `.htaccess` для Apache (Timeweb); сборка кладёт его в `dist/.htaccess` (на Vercel не кладёт).
- `set-domain.sh` — смена адреса в уже собранном сайте или zip-архиве без node.
- `pack-timeweb.sh` — упаковка `dist/` в zip для хостинга.

```bash
npm install
npm run build   # → dist/
```

Как заменить фото первого экрана:

- проще всего — положить картинку как `hero/hero.jpg` (или `.png`, `.webp`, `.avif`; от 1600 px по ширине, пропорции 4:3). Такой файл используется вместо base64-частей, их можно удалить;
- если файл можно добавить только текстом: `base64 -w 76 photo.avif > hero/hero.avif.b64` (одним файлом или частями `hero.avif.b64.1`, `.2`, … — части склеиваются по номеру), старые части удалить.

Из этого файла сборка делает `hero.webp` (до 1920 px), вертикальный кадр для телефона `hero-m.webp` и картинку для соцсетей `og.jpg`.

Содержимое `dist/` — обычные файлы, его можно скопировать на любой хостинг как есть. Внешний сервис на странице только один: карта Яндекса (iframe). Google-сервисов, CDN-шрифтов, аналитики Vercel и серверных функций нет; все пути относительные.

## Адрес сайта (SITE_URL)

Абсолютный адрес сайта нужен только в служебных местах — для поисковиков и превью ссылки в мессенджерах:

| Файл | Что |
|---|---|
| `index.html` | `<link rel="canonical">`, `og:url`, `og:image`, `twitter:image`, в JSON-LD — `url` и `image` |
| `sitemap.xml` | `<loc>` главной страницы |
| `robots.txt` | строка `Sitemap:` |

В исходниках (`src/index.html`) вместо адреса стоит метка `__SITE_URL__`, `robots.txt` и `sitemap.xml` генерирует `build.mjs`. Адрес берётся из одной настройки: переменная `SITE_URL` → на Vercel адрес проекта → по умолчанию `https://udacha-hosta.vercel.app` (константа `DEFAULT_SITE_URL` в `build.mjs`). Ссылки на фото, стили, шрифты и разделы страницы — относительные, от домена не зависят.

Сменить адрес — любой из двух способов (результат одинаковый, проверено):

```bash
# 1) пересборка (нужен node)
SITE_URL=https://example.ru npm run build && npm run pack:timeweb

# 2) без node — в уже собранном сайте или прямо в архиве
sh set-domain.sh https://example.ru path/to/site        # распакованная папка (где index.html)
sh set-domain.sh https://example.ru udacha-timeweb.zip  # архив пересобирается на месте
```

Кириллический домен указывайте в punycode (`https://xn--…`). Скрипт сам берёт текущий адрес из `sitemap.xml`, поэтому его можно запускать повторно.

## Перенос на Timeweb

Сборка архива: `npm run build && npm run pack:timeweb` → `../udacha-timeweb.zip` (в корне архива `index.html` и `.htaccess`, без исходников и служебных файлов) и рядом копия `set-domain.sh`.

`.htaccess` (шаблон `hosting/htaccess`, каждый блок в `<IfModule>`, чтобы отсутствие модуля не давало ошибку 500):

- редирект http → https — с учётом заголовка `X-HTTPS`, который передаёт nginx на Timeweb, и `X-Forwarded-Proto`; путь `/.well-known/acme-challenge/` не перенаправляется (выпуск Let's Encrypt);
- редирект `/index.html` → `/`;
- www ↔ без www — заготовка, выключена (домен не выбран): раскомментируйте один вариант;
- заголовки безопасности: `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`; HSTS — заготовка, включать после того, как SSL заработал;
- кэш как на Vercel: картинки и шрифты — год, страница/стили/скрипты — `max-age=0, must-revalidate`; типы `woff2`/`webp`/`avif`/`svg`; сжатие mod_deflate;
- `X-Robots-Tag: noindex` с Vercel НЕ перенесён: там он закрывает черновик, а на настоящем домене сайт должен индексироваться (строка есть в файле закомментированной — для временного домена).

Особенность Timeweb (виртуальный хостинг): картинки, шрифты, css, js и txt там отдаёт nginx, до Apache такие запросы не доходят, поэтому кэш и сжатие из `.htaccess` действуют на страницу и `sitemap.xml`, а для статики работают настройки nginx хостинга. Если файл картинки или стилей заменить под тем же именем, посетители и nginx могут какое-то время видеть старую версию — надёжнее давать новому файлу новое имя.

Загрузка:

1. Привязать домен к сайту и выпустить SSL-сертификат (Let's Encrypt бесплатно: «Домены и SSL» → «SSL-сертификаты»), дождаться статуса «Установлен».
2. Сменить адрес на выбранный домен: `sh set-domain.sh https://example.ru udacha-timeweb.zip` (вместо example.ru — свой домен).
3. Файловый менеджер панели → папка сайта (`public_html`) → удалить заглушку `index.htm` → загрузить zip → «Разархивировать» в текущую папку. `index.html` и `.htaccess` должны лежать прямо в `public_html`.
4. Открыть сайт по http и https: http должен перенаправлять на https, фото, шрифты и карта — грузиться.

Данные: название, адрес, телефон, часы, кухни, цены, рейтинг, фото и отзывы взяты из карточки кафе на Яндекс Картах: https://yandex.ru/maps/org/udacha/1252765675/
